All 34 pre-existing JSON files were hashed before the runs and again afterwards, and every hash is identical.

## Cost per answer

Wall-clock is the full answer: the `knowledge.py` subprocess for the table suite, or `answer_question` for the prose suite. It includes Python startup, retrieval, and the support-cookie subprocess. Tokens are Ollama's `prompt_eval_count` and `eval_count` summed over the answer's model calls. Peak RAM is sampled with `ps` every 0.2 s over the answer window, so very short peaks can be missed. "Hive" is the RSS of the evaluator process tree, including `knowledge.py` and `support_cookie.py`. "Ollama" is the RSS of the ollama and llama-server processes. On Apple unified memory, GPU-resident weights may not be fully reflected in RSS.

## Unplanned extra prose run (disclosure)

`evaluate_prose_policy.py` has no argument parser: it treats `sys.argv[1]` as its output directory. Running `python3 evaluate_prose_policy.py --help` to check its arguments therefore executed one full live run on the current code and wrote it to `./--help/`. That run used the script's hardcoded gemma4:e4b, seeds 11/29/47, and temperature 0.2, and scored 3/3 `supported_answer` (`inspection_required`). Its summary is kept as `rerun-2026-09-26-prose-unplanned-246ffdb1.json`. The directory was moved out of the repository, and no existing files were affected. It has no timing or RAM measurements; the official prose rerun is `rerun-2026-09-26-prose-c05d54e7.json`.

## Limits

These are the same tuned regression fixtures as before: 21 trials, one model shared by both cookies, and three seeds. A rerun that reproduces earlier results shows the prompt change did not break these cases. It is not a fresh holdout and not a general accuracy measure. Per-answer peak RAM is sampled rather than exact, and the Ollama figure is shared by all answers, not attributable to any single one.
